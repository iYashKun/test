VoiceAfy / Shudh TTS

High-quality Indian & multi-accent Text-to-Speech API with TOTP MFA, one-time tokens, device binding, and unique hashed audio URLs.

Live API
https://voiceafy.vercel.app
UI: /home · Health: /health · Setup: /auth/setup

Overview

VoiceAfy converts text into natural-sounding speech using Google TTS (gTTS) with Indian and international accents. Unlike a simple open endpoint, every request goes through a multi-layer security funnel:

  • TOTP MFA — Authenticator app (Google / Authy / Microsoft)
  • 1-hour Grant — encrypted httpOnly cookie after successful TOTP
  • One-time Token — short-lived (≈90s), single-use
  • HMAC-SHA256 signature — per-request integrity check
  • Nonce + timestamp — replay protection
  • Unique audio hash — clean URLs like /audio/a1b2c3d4e5f67890

Permanent API keys are never required in the browser after setup. Anyone who has the shared TOTP secret in their authenticator can obtain a temporary grant.

Quick Start (UI)

  1. Open the app
    Go to https://voiceafy.vercel.app/home
  2. Get the TOTP secret
    On the Setup screen, copy the secret (or open /auth/setup).
  3. Add to Authenticator
    Open Google Authenticator / Authy / Microsoft Authenticator → Add account → Enter a setup key → paste the secret → save.
  4. Verify TOTP
    Enter the current 6-digit code → you receive a 1-hour grant (httpOnly cookie). Device fingerprint is bound automatically.
  5. Generate voice
    Choose language, type text, click Generate Voice. Play or download the MP3. A unique hash URL is also shown.
Important: Grant expires after 1 hour. After that you must enter a fresh TOTP code again. One-time tokens expire in ~90 seconds and can be used only once.

How It Works

Request funnel

# High-level flow
1. User adds TOTP secret to Authenticator app
2. POST /auth/verify-totp  { totp, device_fp }
   → Server verifies TOTP
   → Sets httpOnly cookie shudh_grant (1 hour)
3. POST /auth/one-time     (cookie required)
   → Returns oneTimeToken + signingKey (~90s)
4. Client builds signature:
   HMAC-SHA256(signingKey, timestamp|nonce|lang|text)
5. POST /tts
   Headers: Cookie + X-One-Time-Token
   Body: { text, lang, timestamp, nonce, signature }
6. Server validates everything → generates MP3
   → Saves as /audio/{unique_hash}.mp3
   → Returns audio/mpeg + X-Audio-Hash header

Unique hash system

Every successful generation creates a 16-character hash derived from text + language + UUID + timestamp. The file is stored and served at: 

GET https://voiceafy.vercel.app/audio/{hash}

Example: https://voiceafy.vercel.app/audio/a1b2c3d4e5f67890

Authentication (TOTP MFA)

There is no long-lived API key in the browser. Access is granted only after a valid TOTP code.

1. Get setup data

GET /auth/setup 
{
  "secret": "JBSWY3DPEHPK3PXP",
  "provisioning_uri": "otpauth://totp/...",
  "instructions": [ ... ]
}

2. Verify TOTP & get grant

POST /auth/verify-totp 
{
  "totp": "482193",
  "device_fp": "a1b2c3d4...",
  "theme": "dark"
}

On success the response sets an httpOnly cookie shudh_grant valid for 1 hour. All subsequent authenticated requests must send this cookie (credentials: "include" in fetch).

3. Mint one-time token

POST /auth/one-time 
{
  "oneTimeToken": "...",
  "signingKey": "...",
  "expires_in": 90
}

4. Logout

POST /auth/logout

Invalidates the current grant and clears the cookie.

API Reference

Generate speech

POST /tts Auth required

Headers

  • Content-Type: application/json
  • X-One-Time-Token: <token>
  • Cookie: shudh_grant=... (automatic with credentials)

Body

{
  "text": "नमस्ते दुनिया",
  "lang": "h:ind",
  "timestamp": 1735689600,
  "nonce": "a1b2c3d4e5f67890...",
  "signature": "hex-hmac-sha256...",
  "ticket_id": null
}

Signature formula (client)

payload   = `${timestamp}|${nonce}|${lang}|${text}`
signature = HMAC-SHA256(signingKey, payload)   // hex

Response

  • Body: raw audio/mpeg (MP3)
  • Header X-Audio-Hash — 16-char unique hash
  • Header X-Audio-URL — e.g. /audio/a1b2c3d4e5f67890

Serve hashed audio

GET /audio/{unique_hash} Public

Returns the previously generated MP3 if it still exists on the server.

Ticketing System

Optional usage tickets for tracking or soft quota. Each grant can create a limited number of tickets.

POST /tickets/create Auth required 
{ "purpose": "tts", "note": "optional note" }
GET /tickets/mine

You can attach a ticket_id in the TTS body. Once used, the ticket is marked consumed.

Security Model

  • No permanent API key in the browser after TOTP verification
  • httpOnly + Secure cookie for the 1-hour grant (not readable by JS)
  • Device fingerprint collected and bound at grant time
  • IP logged with the grant
  • Single-use one-time tokens (~90 seconds)
  • HMAC-SHA256 over timestamp|nonce|lang|text
  • Nonce uniqueness prevents replay attacks
  • Timestamp window (~90s) blocks old requests
  • Rate limiting per IP
  • Constant-time comparisons for secrets

Common Error Codes

StatusMeaningWhat to do
401 Invalid / expired TOTP, grant, token, or signature Re-verify TOTP or mint a new one-time token
429 Rate limit exceeded Wait ~60 seconds and retry
400 Empty text, invalid ticket, bad hash Check request body / parameters
404 Audio hash not found / expired Regenerate the voice
500 TTS engine failure Retry; check text length / language

What Not To Do

  • Do not put the TOTP secret in client-side code or public repos.
  • Do not reuse one-time tokens — they are single-use only.
  • Do not call /tts with GET or put text in the URL.
  • Do not share your live Authenticator codes with others.
  • Do not ignore rate limits — aggressive polling will be blocked.
  • Do not expect audio files to live forever (server may clean old files).
  • Do not send text longer than 3000 characters.
  • Do not rely on the default TOTP secret in production — set SHUDH_TOTP_SECRET and SHUDH_HMAC_SECRET in environment variables.

Use Cases

1. Web / App voice feedback

Convert UI messages, notifications, or form confirmations into spoken Hindi / Indian English.

2. Accessibility

Read page content aloud for users who prefer audio, especially in regional languages.

3. Content & learning

Generate voiceovers for short videos, language learning clips, or podcast intros.

4. Customer support bots

Turn chatbot replies into speech with a consistent Indian accent.

5. Temporary shareable audio links

Generate a unique hash URL and share /audio/{hash} without exposing the original text in the path.

Limits & Practical Tips

  • Text length: 1–3000 characters per request
  • Grant lifetime: 1 hour after successful TOTP
  • One-time token: ~90 seconds, single use
  • Rate limit: roughly 20 requests per minute per IP
  • Audio storage: temporary; older files may be cleaned
  • Serverless note: On Vercel, in-memory state (grants, nonces) resets on cold starts. Prefer short sessions and re-verify TOTP when needed.

Example: full client flow (fetch)

// 1. After user enters TOTP
await fetch('https://voiceafy.vercel.app/auth/verify-totp', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ totp: '123456', device_fp: fp })
});

// 2. Get one-time token
const tok = await fetch('https://voiceafy.vercel.app/auth/one-time', {
  method: 'POST', credentials: 'include'
}).then(r => r.json());

// 3. Sign and call /tts
const timestamp = Math.floor(Date.now() / 1000);
const nonce = cryptoRandomHex(16);
const payload = `${timestamp}|${nonce}|h:ind|${text}`;
const signature = await hmacSha256(tok.signingKey, payload);

const res = await fetch('https://voiceafy.vercel.app/tts', {
  method: 'POST',
  credentials: 'include',
  headers: {
    'Content-Type': 'application/json',
    'X-One-Time-Token': tok.oneTimeToken
  },
  body: JSON.stringify({ text, lang: 'h:ind', timestamp, nonce, signature })
});
const mp3 = await res.blob();
